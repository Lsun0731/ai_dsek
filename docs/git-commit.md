# Git 提交规范（AiDesk）

## 核心原则

提交信息写**变更本身**——实现了什么功能、改了什么——**不写**：

- ❌ 需求来源 / 用户说了什么（"用户要求…"、"我想到…"）
- ❌ 对话背景 / 决策过程
- ❌ 实现步骤流水账（"先 A 再 B 再 C"）

读者看提交历史时，关心的是"这个提交做了什么"，不是"当初为什么提这个需求"。

## 格式

```
<type>(<scope>): <摘要>
```

- `type` 必填，`scope` 可选（模块名，如 `pet`、`search`、`widgets`）
- 摘要：**一句话**，≤ 30 个汉字，动词开头（实现 / 新增 / 修复 / 重构 / 移除 / 统一 / 优化 / 补充）

## type 类型

| type | 含义 | 示例 |
|---|---|---|
| `feat` | 新功能 | `feat: 新增 AI 对话 Tab` |
| `fix` | 修复缺陷 | `fix: 修复搜索面板控件重叠` |
| `refactor` | 重构（行为不变） | `refactor: Agent 工具抽公共类` |
| `style` | UI 样式调整 | `style: 小组件统一 Mica 风格` |
| `perf` | 性能优化 | `perf: 应用扫描结果缓存` |
| `docs` | 文档 | `docs: 新增提交规范` |
| `test` | 测试 | `test: 补充工具调用用例` |
| `chore` | 杂项（依赖 / 构建 / 清理） | `chore: 清理未使用代码` |

## 摘要写法

✅ 写"实现了什么"：

```
feat: 宠物改纯语音对话（唤醒词 + TTS 回复）
fix: 语音引擎释放顺序
style: 搜索面板换 Win11 Mica 风格
```

❌ 不写需求 / 过程 / 堆砌：

```
feat: 用户想要宠物可以用麦克风说话，然后回复也能用语音，还要一个唤醒词叫 AD AD……
fix: 先取消识别再释放引擎防止跳过 HttpClient 释放（先 A 再 B 再 C 的流水账）
```

❌ 一个提交塞多个无关变更——拆开（无法拆的关联改动可并列用 `；` 分隔，最多 2-3 项）：

```
feat: 宠物改纯语音对话（唤醒词 + TTS 回复）；文字聊天移入搜索面板 AI Tab
```

## 正文（可选）

需要解释 **Why**（为什么这么改）时，空一行写短句，一行一条：

```
fix: 语音引擎释放顺序

识别中关窗会跳过 HttpClient 释放，先取消再 Dispose
```

日常提交通常不需要正文。

## 正反例（本项目实际提交）

- ❌ 旧：
  `feat: 宠物纯语音对话——常驻监听唤醒词「AD AD」（兼容阿迪阿迪等变体）→ 提示「我在，请说」+ 提示音 → 自动听写 → AI Agent 回复（气泡文字 + 中文 TTS 朗读）→ 回待命；点击宠物=直接听写；移除宠物文字输入；文字聊天移入搜索面板新 Tab「AI 对话」（多轮记忆 + Agent 工具）；Agent 工具抽公共 AgentTools`
- ✅ 新：
  `feat: 宠物改纯语音对话（AD AD 唤醒词 + TTS 回复）；文字聊天移入搜索面板 AI Tab`

## 可选：提交模板

仓库根目录提供 `.gitmessage`，执行一次：

```powershell
git config commit.template .gitmessage
```

之后 `git commit` 会打开模板提示填写。
